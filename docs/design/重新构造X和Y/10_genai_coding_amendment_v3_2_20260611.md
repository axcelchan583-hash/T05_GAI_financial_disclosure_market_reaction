# T05 GenAI 公告编码增补 v3.2：GenAI 认定亮线与 INFRA 标签（20260611）

生效日期：2026-06-11

本文件是 `08_genai_announcement_experiment_design_v3_1_20260610.md` 的增补，不替代 v3.1。
v3.1 的判定树（`A / B / C / D-fw / D / U`）、A 类附加字段（`OUT/M/R`）、框架协议亮线、
投资两 gate 全部继续有效。本增补只解决一个在 DeepSeek V4-Pro 复核中暴露的口径分歧：

> 算力服务器 / 智算中心 / 算力租赁等 AI 基础设施类公告，算不算 GenAI initiative？

## 1. 分歧来源

v3.1 第 6 节投资 gate 2 原文：

```text
标的是否明确 GenAI 相关：大模型训练/推理、AIGC 服务、或服务具体大模型公司
```

这条规则存在两种读法：

- 字面窄读：公告对产出/标的的描述必须明确出现大模型/AIGC/生成式 AI；
- 语境宽读：以 ChatGPT 热潮为动因、整合大模型芯片伙伴、布局算力链即可。

典型冲突案例：弘信电子（300657，2023-07-23，天水 AI 算力服务器智造项目）。
DeepSeek V4-Pro 按窄读判"泛 AI 基础设施，未明确指向生成式 AI"；
人工按宽读可判 A（承诺真实：一期 2 亿、需股东大会审议、厂房工期写死）。

而 v3.1 自带的示例（鑫煜科技增资星临科技，证据原文"为国产大模型研发训练提供算力服务"，
判 `A | M=ext`）说明宽窄分界其实落在证据文本本身：鑫煜的标的描述明确写了"大模型"，
弘信的产出描述只有"AI 算力服务器"，ChatGPT 仅出现在投资目的的行业背景段。

## 2. 新增亮线：GenAI 认定看产出/标的描述，不看背景段

自本增补生效起，投资 gate 2 与所有类别的 GenAI 认定统一采用：

```text
GenAI 认定亮线：
    公告对产出 / 标的 / 交付物的描述文本中，明确出现
    大模型 / 生成式AI / AIGC / GPT类产品 / 具体大模型名称或具体大模型公司，
    才认定为 GenAI 相关。

    仅在投资目的、行业背景、风险提示等段落提及
    ChatGPT热潮 / AI浪潮 / 人工智能机遇，不构成 GenAI 认定。
```

对照判例：

```text
鑫煜科技 -> 星临科技："为国产大模型研发训练提供算力服务"
    标的描述明确指向大模型 -> 过线 -> A | M=ext

弘信电子 -> 天水算力服务器项目："年产10万台AI算力服务器智能制造基地"
    产出描述为泛 AI 硬件，ChatGPT 仅在背景段 -> 不过线 -> D | INFRA=1
```

## 3. 新增标签：INFRA

为避免把"算不算 GenAI"的边界裁量变成不可逆的样本删除，新增一个标签字段：

```text
INFRA=1    算力服务器 / 智算中心 / 算力租赁 / AI芯片制造等
           AI 基础设施类公告，产出描述未过 GenAI 认定亮线
INFRA=0    （默认，可不写）
```

使用规则：

1. 承诺真实但产出描述未过 GenAI 亮线的基础设施类公告，判 `D | INFRA=1`；
2. 产出描述过线的算力类公告（如鑫煜案例）正常判 A，可加 `INFRA=1` 标注其基础设施属性；
3. `D | INFRA=1` 保留公告日与全部字段，便于后续作为
   "compute-infrastructure announcement" 对照样本或宽口径稳健性样本一键召回。

示例：

```text
人工码: D | INFRA=1 | 证=拟建设年产10万台AI算力服务器智能制造基地
人工码: A | OUT=1 | M=ext | INFRA=1 | 证=标的为国产大模型研发训练提供算力服务 | R=-
```

## 4. 澄清 D 与 D-fw 的边界：两个维度，不是一条轴

v3.1 的判定码隐含两个独立维度：

```text
              承诺可信                承诺不可信/无实质承诺
GenAI 真      A                      D-fw（保留公告日，cheap-talk placebo）
GenAI 弱/泛   D | INFRA=1（保留公告日） D（不保留）
```

关键澄清：

- `D-fw` 只收"GenAI 话题真、承诺假"的框架协议/意向性公告；
- "承诺真、GenAI 指向弱"的基础设施类公告判 `D | INFRA=1`，**不得**放入 `D-fw`，
  否则污染 cheap-talk placebo 池；
- 弘信电子案例两条亮线都要过：框架协议亮线它过了（有金额、需股东大会审议），
  GenAI 认定亮线它没过——所以是 `D | INFRA=1`，不是 `D-fw`，也不是 A。

## 5. 主样本与稳健性口径

```text
headline 主样本：
    verdict=A（窄口径，产出描述过 GenAI 认定亮线）

并行/稳健性：
    A + (D|INFRA=1 中承诺真实者) 宽口径重跑主表，
    报告"含算力基础设施事件"的结果作为 extension；
    INFRA=1 子样本单独的 competitor CAR 可作为
    "产能扩张 vs GenAI 能力信号"的机制区分证据。
```

理由：论文机制是市场把可信 GenAI 披露定价为对 product-market competitors 的
横向竞争威胁。算力基建公告对硬件同行的负溢出可以来自普通产能扩张竞争，
与 GenAI 能力信号不可分，混入 headline 会被攻击为 capex announcement spillover。

## 6. 对存量编码与 DeepSeek 流程的处置

1. **冲突归因统计**：先统计 v49/v50 的 38+1 条 machine/V4-Pro 冲突中，
   有多少条属于本口径问题（算力/智算中心/基础设施边界），按本亮线批量重判，
   不逐条裁量；
2. **已审 118 条**：凡涉及算力/基础设施的已审案例，按第 2、4 节规则复核一遍
   verdict 与 INFRA 标签；
3. **DeepSeek prompt 更新**：把第 2 节亮线与第 4 节 2×2 边界写入预编码 prompt，
   对剩余未审的机器 A/B/D-fw 队列重跑，并记录口径更新前后的一致率变化；
4. **D 类抽样审计**：5%-10% 抽样时对 `D` 中的算力类案例优先抽取，
   防止本应 `D | INFRA=1` 保留公告日的案例被当普通 D 丢弃。
