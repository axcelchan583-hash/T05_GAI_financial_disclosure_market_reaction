# T05 GenAI 公告编码增补 v3.2：GenAI 链内性亮线与 LAYER 标签（20260611）

生效日期：2026-06-11
同日修订：初版采用"窄口径 headline + INFRA 标签"，经样本量核查后改为
"GenAI 产业链宽口径 headline + LAYER 四层标签"。修订理由见第 1、5 节。

本文件是 `08_genai_announcement_experiment_design_v3_1_20260610.md` 的增补，不替代 v3.1。
v3.1 的判定树（`A / B / C / D-fw / D / U`）、A 类附加字段（`OUT/M/R`）、框架协议亮线、
投资两 gate 全部继续有效。本增补解决 DeepSeek V4-Pro 复核中暴露的口径分歧：

> 算力服务器 / 智算中心 / 算力租赁等 AI 基础设施类公告，算不算 GenAI initiative？

## 1. 分歧来源与口径决定

v3.1 第 6 节投资 gate 2 原文"标的是否明确 GenAI 相关：大模型训练/推理、AIGC 服务、
或服务具体大模型公司"存在窄读（交付物描述必须明确写大模型/AIGC）与宽读
（GenAI 算力链即可）两种执行方式。典型冲突案例：弘信电子
（300657，2023-07-23，天水 AI 算力服务器智造项目），DeepSeek V4-Pro 按窄读
判"泛 AI 基础设施"，人工按宽读可判 A。

口径决定：**采用 GenAI 产业链宽口径**。

理由：

1. 样本现实：v50 类别分布中"产品/平台/模型发布"仅 11/100，纯模型/AIGC 发布类
   事件预计仅 20–40 条，无法支撑 event FE 下的 `Spec × AIActivePeer` 设计；
2. 理论自洽：焦点公司在 GenAI 价值链上的可信卡位（含算力层）对其
   product-market peers 构成横向竞争威胁，机制不要求焦点公司自己造模型；
3. 代价：X 必须表述为 "GenAI value-chain initiative disclosure"，
   不得表述为 "GenAI capability disclosure"，并配齐第 5 节防守。

## 2. 链内性亮线：边界卡在"GenAI 链 vs 泛 AI"

GenAI 认定改为两问：

```text
问1 可信性：承诺可信吗？
    v3.1 框架协议亮线 + 投资两 gate 中的"承诺真实"gate，原封不动。

问2 链内性：交付物/标的落在 GenAI 四层链内吗？

链内（可进 A，必须打 L= 标签）：
    L=model    自研/发布/备案大模型、行业大模型
    L=app      基于大模型的 AIGC 产品/服务/功能
    L=compute  大模型训练/推理算力：AI服务器、智算中心、算力租赁、AI芯片
    L=data     面向大模型的语料/标注/数据服务

链外（判 D，泛 AI）：
    传统 CV/安防/质检/语音/推荐/自动驾驶等非生成式 AI；
    交付物与四层无关、仅在投资目的/行业背景/风险提示段落
    提及 ChatGPT/AI 热潮的。
```

说明：

- "背景段提 ChatGPT 不算"继续有效，但它挡的是泛 AI 蹭热点；
  算力层交付物（AI 服务器、智算中心、算力租赁）本身即大模型训练/推理
  专用资产，链内性由交付物类型直接认定，不依赖背景段表述；
- 交付物层级模糊、无法归入四层的，判 `U` 二次核验。

对照判例：

```text
鑫煜科技 -> 星临科技："为国产大模型研发训练提供算力服务"
    -> A | L=compute | M=ext

弘信电子 -> 天水项目："年产10万台AI算力服务器智能制造基地"，
    一期2亿、需股东大会审议、厂房工期明确
    -> A | L=compute | OUT=1 | M=own | R=-

某公司"智慧城市平台全面引入AI能力"，背景段提ChatGPT
    -> D（泛AI，链外）
```

## 3. LAYER 标签使用规则

1. 所有 `A` 类必须打 `L=model/app/compute/data` 之一；
2. `D-fw` 类建议同样打 `L=` 标签（话题所属层），便于 cheap-talk 对照分层；
3. 一份公告涉及多层时取最具体/承诺最重的一层，并在`证=`中保留依据；
4. 已审 118 条中涉及算力/基础设施的案例按本节补打标签。

示例：

```text
人工码: A | OUT=1 | M=own | L=compute | 证=一期预计总投资2亿元，拟建设年产10万台AI算力服务器智能制造基地 | R=-
人工码: A | OUT=1 | M=own | L=model | 证=公司发布讯飞星火认知大模型并同步发布商业应用成果 | R=+
人工码: D-fw | L=compute
```

## 4. 澄清 D 与 D-fw 的边界：两个维度，不是一条轴

```text
              承诺可信                    承诺不可信/无实质承诺
链内（四层）   A | L=...                  D-fw | L=...（保留公告日，cheap-talk placebo）
链外（泛AI）   D                          D
```

关键澄清：

- `D-fw` 只收"链内话题真、承诺假"的框架协议/意向性公告；
- 链外泛 AI 公告无论承诺真假一律 `D`，不得进入 `D-fw`，
  否则污染 cheap-talk placebo 池；
- 弘信电子两条亮线都过（承诺可信 + L=compute 链内），判 A，
  既不是 D-fw 也不是 D。

## 5. 实证防守：宽口径 headline 的三件配套

X 定义为 GenAI 产业链宽口径后，必须在主表附近配齐：

1. **层间异质性表**：`L=model/app` vs `L=compute` 分层报告 competitor CAR 与
   `Spec × AIActivePeer`，作为主表后第一张表。若仅 compute 层显著，
   叙事须改写为算力卡位竞争，不得继续写 GenAI 能力信号；
2. **非 AI 投资公告 placebo**：同公司或匹配公司的普通对外投资/扩产公告
   -> peer CAR，直接回应"任何 capex 公告都会压同行"的攻击；
3. **A vs D-fw cheap-talk 对照**（v3.1 第 8.4 节）承担可信性维度防守。

## 6. 对存量编码与 DeepSeek 流程的处置

1. **冲突归因统计**：统计 v49/v50 的 38+1 条 machine/V4-Pro 冲突中，
   有多少条属于本口径问题（算力/智算中心/基础设施边界），按第 2 节亮线
   批量重判，不逐条裁量；
2. **已审 118 条**：涉及算力/基础设施的已审案例按第 2、3、4 节复核
   verdict 并补打 `L=` 标签；
3. **DeepSeek prompt 更新**：把第 2 节两问亮线、四层定义与第 4 节 2×2 边界
   写入预编码 prompt，对剩余未审队列重跑，并记录口径更新前后的一致率变化；
4. **D 类抽样审计**：5%-10% 抽样时优先抽取算力类与"背景段蹭热点"类案例，
   分别防漏保（本应 A|L=compute）和防误收；
5. **层分布统计**：每完成约 100 条，统计 A 类的 `L=` 分布。
   若 `L=model/app` 占比过低导致层间异质性表失去意义，
   需回到本文件重议口径。
